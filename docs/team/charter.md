# 니디드 개발 팀 헌장

2026-11-28에 사용자와 정했다. 팀의 모든 에이전트는 일을 시작하기 전에 이 문서를 읽는다.

## 1. 무엇을 만드는가

**니디드**는 여행 일정을 짜 주는 앱이다. 핵심은 둘이다.

1. AI가 가장 좋은 경로와 일정을 짠다.
2. 항목마다 AI가 대안을 추천한다. 바꾸면 이동과 경비를 다시 계산한다.

사용자가 읽는 기획안은 `docs/report/planning-report.html`이다. 기술 설계는 `docs/superpowers/specs/`에 있다.

## 2. 첫 목표

**첫 사용 장면을 하나로 정한다.** 팀은 이 장면이 끝까지 돌아가게 만든다.

- 언제: 2026-12-05(토) ~ 12-06(일), 1박 2일
- 어디: 경주
- 누구: 다섯 명. 어머니, 여동생 부부, 사용자 부부.
- 조건: 어르신이 함께 간다. 많이 걷지 않는다.

**팀의 완료 지점은 "초대한 사람이 쓰는 웹 앱"이다.** 공개와 결제는 그다음이다.

## 3. 단계와 완료 기준

기준을 모두 채워야 단계가 끝난다. "거의 됐다"는 끝난 것이 아니다.

| 단계 | 만드는 것 | 완료 기준 |
|---|---|---|
| 1 핵심 로직 | 저장소 구조, 조건 합치기, 일정 모델, 순서 짜기, 대안 교체와 재계산 | ① 테스트가 모두 통과한다. ② 경주 장면을 넣으면 일정이 나온다. ③ 꼭 갈 곳이 하나도 빠지지 않는다. ④ 걷는 한도를 넘는 구간이 표시된다. ⑤ 대안으로 바꾸면 걷는 시간과 경비 합계가 바뀐다. |
| 2 웹 화면 | 질문 세 화면, 일정표(일정·숙소·경비), 대안 교체 | ① 브라우저에서 경주 장면을 처음부터 끝까지 누를 수 있다. ② 휴대폰 폭에서 가로로 넘치지 않는다. ③ 화면 테스트가 통과한다. |
| 3 실제 데이터 | AI와 지도 API 연결, 확인 기록, 비용 기록 | ① 실제 API로 경주 일정이 나온다. ② 항목마다 확인 상태와 근거가 붙는다. ③ 일정 한 건의 비용이 기록된다. 키가 있어야 시작한다. |
| 4 계정과 저장 | 로그인, 초대 코드, DB, 공유 링크 | ① 초대 코드로 가입한다. ② 일정이 저장되고 다시 열린다. ③ 링크를 받은 사람이 가입 없이 본다. |
| 5 여행 중 | 다녀온 곳 기록, 다시 추천, 빈 시간 추천 | ① 버튼으로 방문을 기록한다. ② 다음 일정을 바꾸면 뒤 일정이 맞춰진다. ③ 빈 시간을 넣으면 걸어서 갈 곳이 나온다. |

**키가 없을 때.** 1단계와 2단계는 키 없이 한다. 경주 데이터는 직접 확인해서 `data/`에 둔다. 확인하지 못한 값은 "확인 전"으로 표시한다.

## 4. 역할

| 역할 | 목적 | 맡는 곳 | 하지 않는 것 |
|---|---|---|---|
| 총괄 | 목표와 순서를 정한다. 일을 나누고 결과를 검토한다. 사용자에게 보고한다. | `docs/team/`, 브랜치 합치기 | 검수 없이 합치지 않는다. 기준을 낮추지 않는다. |
| 기획·화면 | 화면과 문구를 정한다. 기획안과 앱이 어긋나지 않게 한다. | `docs/report/`, 화면 문구 | 기능을 임의로 더하거나 빼지 않는다. |
| 서버 | API, 작업 처리, DB를 만든다. | `apps/api`, `apps/worker`, `packages/db` | 화면 코드를 고치지 않는다. |
| 화면 개발 | 웹 화면을 만든다. | `apps/web` | 서버 규칙을 화면에 다시 짜지 않는다. 계산은 핵심 로직을 부른다. |
| AI·추천 | 순서 짜기, 대안 추천, 조건 합치기를 만든다. | `packages/core` | 이동 시간을 지어내지 않는다. 계산하거나 받아 온 값만 쓴다. |
| 데이터·확인 | 장소 데이터와 확인 기록을 만든다. 지도·검색 연결을 맡는다. | `packages/providers`, `data/` | 확인하지 않은 것을 확인됨으로 적지 않는다. 출처 없는 값을 넣지 않는다. |
| 검수 | 완료 기준을 하나씩 확인한다. 코드를 검토한다. | 테스트, 검토 기록 | 직접 고치지 않는다. 문제를 적어 돌려보낸다. |

## 5. 모두가 지키는 것

**하지 않는다.**

- 광고, 제휴 수수료, 순위 판매와 관련된 코드를 넣지 않는다.
- 확인하지 않은 것을 "확인됨"으로 표시하지 않는다.
- 사용자가 적은 꼭 갈 곳을 묻지 않고 빼지 않는다.
- 테스트를 건너뛰거나 꺼서 통과시키지 않는다.
- 비밀 키를 저장소에 올리지 않는다.
- 기존 `index.html`을 고치지 않는다.
- 맡은 곳 밖의 파일을 고치지 않는다. 필요하면 총괄에게 알린다.

**한다.**

- 테스트를 먼저 쓴다.
- 끝났다고 말하기 전에 직접 돌려 본다. 돌려 본 결과를 함께 적는다.
- 글은 `CLAUDE.md`의 글쓰기 규칙을 따른다.

## 6. 누가 정하는가

| 묻지 않고 정한다 | 반드시 사용자에게 묻는다 |
|---|---|
| 코드 구조, 라이브러리, 이름 | 돈이 드는 일 |
| 테스트 방법 | 외부에 공개하는 일 |
| 화면의 세부 배치 | 파일이나 데이터를 지우는 일 |
| 예시 데이터 | 기본 브랜치(`main`)에 합치는 일 |
| | 범위를 바꾸는 일. 기능을 더하거나 빼는 것. |

## 7. 일하는 법

- 작업은 `claude/clever-euler-xkbzmy` 브랜치에 모은다.
- 일을 작게 나눈다. 한 번에 하나의 기준을 채운다.
- 만든 사람과 검수하는 사람은 다르다.
- 같은 일에 세 번 실패하면 멈추고 총괄에게 알린다. 총괄은 사용자에게 보고한다.
- 막히면 물을 것을 남기고 다른 일을 계속한다.

## 8. 보고

단계가 끝날 때마다 사용자에게 알린다. 보고에는 세 가지를 적는다.

1. 채운 기준과 그 증거. 테스트 결과, 화면.
2. 채우지 못한 것과 이유.
3. 사용자가 정해야 할 것.

## 9. 사용자가 준비할 것

| 무엇 | 언제 필요한가 |
|---|---|
| Claude API 키 | 3단계 |
| 지도 API 키. 카카오, 티맵, 구글 | 3단계 |
| DB를 둘 곳 | 4단계 |
| 카카오 로그인 앱 등록 | 4단계 |

## 10. 정해진 제품 결정

- 저장소는 이 저장소를 쓴다. 새로 만들지 않는다.
- 웹 먼저, 휴대폰 앱은 나중.
- 국내 먼저. 첫 도시는 경주.
- 수익은 구독과 건당 결제뿐. 첫 여행은 무료.
- 방문 기록은 버튼으로 한다.
- 시간이 정해진 일정도 받는다. 그 시간은 움직이지 않는다.
- 웨이팅 같은 값은 리뷰에서 AI로 뽑고 사용자 제보로 고친다.
- 기술은 Next.js 웹, TypeScript 서버, PostgreSQL. A2UI는 여행 중 추천에만 쓴다.
